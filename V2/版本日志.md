# V2 版本日志 —— 废案（Python + pywebview 的钉子/缩放试验线）

> 状态：⛔ 已废弃（废案）
> 本版包含：`版本日志.md`、`源码参考/`（该路线最终一版源码）、
> `附-废案最终运行版.exe`、`附-免安装分享包.zip`（仅供查看效果，不建议日常使用）

## 这是什么版本

在 V1 稳定版基础上，试验性地加入桌面窗口的“高级交互”：
置顶钉子、窗口缩放、拖动移动、随窗口自适应布局。
包含多次中间构建（V2.x），最终因**稳定性达不到可用标准**整条废弃。

## 尝试实现的功能

- **置顶钉子**：右上角图钉按钮，激活后窗口常驻最上层；尝试过多种激活样式
  （旋转、光晕、渐变底、白底+深蓝实心钉子等）。
- **窗口缩放 / 拖动移动**：
  - 第一版：固定比例“缩放层”（以 420x404 设计稿等比缩放整个界面），
    又尝试原生缩放宽边（`WS_THICKFRAME`）与右下角手柄；
  - 最终版：窗口边缘/四角热区缩放 + 空白处拖动移动（自绘窗口控制）。
- **流式自适应布局**：删除“正方形缩放层”，让圆环/文字按窗口宽高重新排版。

## 出过错 / 踩坑记录（主要废案原因）

1. **WebView2 偶发“未响应”贯穿始终**：本机渲染层会无故冻结（甚至未操作就卡死），
   曾用：关闭 GPU/合成加速、屏蔽遮挡计算、启动看门狗自动重启、运行时心跳自愈缓解，
   仍会中断使用，判定为旧路线不可靠 → 废弃。
2. 原生缩放宽边导致窗口顶部出现白色未填充区域（窗口度量与 WebView2 不同步）。
3. 固定比例缩放层让窗口看起来像“正方形卡片”，拉宽/拉高不变形，不符合预期。
4. 缩放光标一度显示为“抓手”而不是双向箭头（整个卡片被设成拖拽区所致）。
5. 自绘拖动曾完全失效：读取窗口坐标的 `GetWindowRect` 漏写 64 位参数声明，
   坐标查询必失败 → 移动/缩放都没有基准（已修复但已不值得继续投入）。

## 完成度

- 功能层面：约 80%（交互大体成型、UI 会自适应、钉子样式迭代多轮）。
- **稳定性层面：不合格**（间歇性未响应影响日常操作），故整条线废弃。
- 结论：**不要在日常环境使用 V2**；如需旧版可用程序请用 V1。

## 给后续（V2.1 Electron）的教训

- 渲染内核稳定性是第一优先级；别再在 WebView2/pywebview 上修补。
- 无边框窗口的缩放/拖动应优先考虑成熟方案，避免自绘带来的光标与白边问题。
- 界面代码（`balance-widget.html`）与视觉设计可以整体复用到 Electron。
